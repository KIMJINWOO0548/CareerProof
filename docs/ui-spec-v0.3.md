# CareerProof UI 명세 v0.3

근거를 확인하며 한국어 지원서를 작성하고, 문항별 제한에 맞춘 확정본을 제출 화면으로 가져가는 로컬 워크벤치다. 행동과 성과를 읽는 작업이 중심이므로 편집 본문과 근거를 같은 화면에서 오갈 수 있게 한다. 작성 제안의 채택, 심사 시작, 내보내기는 각각 사용자 조작으로 진행한다.

- **상태** `SPECIFIED`. 이 문서는 화면과 상호작용 계약을 정의한다. 실제 제공 범위에는 단계와 검증 상태를 함께 표시한다.
- **기준 설계** [CareerProof 상세 설계서 v0.2.2](./careerproof-design-v0.2.2.md)
- **v0.3 제품 기준** [계산 규칙·심사 루브릭·시연 기록](careerproof-design-v0.3.md)
- **언어** 한국어 우선. `C++`, `WPF`, `Fast`, `Deep`처럼 통용되는 이름은 원래 표기를 사용한다.

## 1. 범위와 정보 구조

| 화면 | 내비게이션 값 | 화면에서 하는 일 | 출시 목표 |
|---|---|---|---|
| 작성 워크벤치 | `workbench` | 문항 선택, 편집, 분량·문체 확인, 제안 비교와 확정 | Phase 1 |
| 프로필·사실 | `profile` | 프로필 가져오기, 사실 후보 확인, 문항별 필수 사실 지정 | Phase 1 |
| 공고·자료 | `brief` | 공고와 문항 직접 입력, 공고 요건·포트폴리오 증거 확인 | 직접 입력 Phase 1, 분석·첨부 Phase 2 |
| 위원회 | `committee` | 심사 범위 설정, 페르소나별 인용과 준비 과제 확인 | Phase 2 |
| 내보내기 | `export` | 선택한 확정 답변 복사·TXT, 작업 JSON 관리 | Phase 1, PDF 선택 Phase 3 |

프로젝트 선택, 저장 방식, 제공자 설정은 상단의 프로젝트 이름과 설정에서 접근한다. 기본 화면은 현재 프로젝트의 작성 워크벤치다. `aria-current="page"`로 활성 화면을 표시하고, 프로젝트와 문항 선택은 화면을 오가도 유지한다. 향후 Answer Bank와 Tracker는 선택 Phase 2.5다. Chrome 확장은 Phase 4에서 내보내기 화면에 연결한다. 크레딧과 계정 관리는 Phase 5에서 별도 설계한다.

### 정적 프로토타입의 화면과 동작

[인터랙티브 시연 열기](./ui/index.html)

첫 진입 시 `가상시스템즈`의 `장비 제어 소프트웨어 개발` 지원 프로젝트를 연다. `지원서 작성`의 `작성 루프`에는 `일시 정지`를 표시한다. 초기 문항은 `지원 동기`이며 제한은 공백 포함 500자다. 다음 문항은 `직무 역량` 700자와 `입사 후 계획` 500자다. `F-001`은 P/Invoke 연동, `F-002`는 120ms에서 85ms로 지연 단축, `F-003`은 타임아웃 테스트 6건을 나타낸다. 세 사실은 예제에서 확인 상태로 준비돼 있다.

| 내비게이션 값 | 화면 제목 | 시연 동작 |
|---|---|---|
| `workbench` | 지원서 작성 | 문항 선택, 본문 편집, 실시간 분량과 규칙 예제, `이어서 진행`과 `일시 정지`의 가상 루프, `수정 제안` 전후 비교와 `제안 반영`·`거절`, `확정 검토` 후 `이 답변 확정` |
| `profile` | 프로필과 사실 원장 | 직접 사실 추가, JSON Resume 경험 항목의 브라우저 미리보기, 후보 추가와 `사실 확인` |
| `brief` | 공고 브리프 | `가상 공고 불러오기`, 공고 붙여넣기, `브리프 반영`으로 명시 요건과 가상 근거 표시 |
| `committee` | 위원회 심사 | 문항·지원서 선택, `시연 심사 실행`, 역할별 가상 의견과 현재 답변의 인용 보기 |
| `export` | 확정본 내보내기 | `답변 복사`, 문항별 `TXT 다운로드`, 탭의 작업 자료 `JSON 다운로드` |

`글자 수 보정` 모달은 `가 나`, 줄바꿈을 넣은 `가`와 `나`, `가😀`의 사이트 표시값으로 문자 수 규칙 후보를 비교한다. `예시 표시값 넣기`는 3·4·3을 채워 공백 포함, 줄바꿈 2자, 이모지 2자 후보를 보여 준다. 부분 입력은 후보 개수와 추가 입력을 안내하고, 불일치에는 사이트의 단위를 확인하도록 안내한다. 편집기의 문항 제한은 시연 데이터의 원래 규칙으로 계산한다.

프로토타입은 브라우저 탭 메모리에서 실행한다. 새로고침하면 가상 예제로 돌아간다. `JSON 다운로드`는 `careerproof-workbench.json`에 회사·직무, 사실, 문항, 제한, 필수 사실 ID, 편집·추천·확정 리비전 참조와 이력을 담는다. 포맷은 `careerproof-prototype`이다. `TXT 다운로드`는 선택한 확정 답변 한 건을 UTF-8로 저장한다. 제품의 프로젝트 복원, 영속 저장, BYOK·실제 심사·외부 리서치·확장 전송은 이후 본문에 지정한 구현 범위다.

### 프로토타입 반응형 동작

| 화면 폭 | 실제 CSS 동작 |
|---|---|
| 1,500px 이상 | 좌측 메뉴 `240px`, 상단 경로 최소 `55px`, 본문과 근거 보조 열 |
| 1,151–1,499px | 좌측 메뉴 `218px`, 상단 경로 최소 `55px`, 본문과 근거 보조 열 |
| 901–1,150px | 좌측 메뉴 `180px`, 상단 경로 최소 `55px`, 좁아진 2열 본문 |
| 731–900px | 한 줄 상단 메뉴와 브랜드, 본문 2열, 상단 경로 최소 `42px` |
| 730px 이하 | 브랜드와 안내 버튼 아래 가로 스크롤 메뉴, 상단 경로 최소 `36px`, 본문·근거·전후 비교를 한 열로 배치 |

시연의 한국어 글꼴에는 `Malgun Gothic`, `Apple SD Gothic Neo`, `system-ui` fallback을 적용한다. 페이지 제목은 `clamp(28px, 2.55vw, 40px)`다.

## 2. 레이아웃과 시각 체계

### 제품 목표 레이아웃

| 화면 폭 | 내비게이션 | 편집과 참조 | 주요 동작 |
|---|---|---|---|
| 1,200px 이상 | 좌측 `216px` 메뉴 및 문항 목록. 상단 `64px` 공통 헤더 | 본문 열 `minmax(0, 1fr)`, 보조 열 `minmax(280px, 336px)`. 편집기·문항 헤더 시작선을 맞추고 본문 읽기 폭은 최대 `760px` | 편집기 아래 카운터와 작업 버튼. 근거 패널 위치를 유지 |
| 768–1,199px | 상단 메뉴, 선택 문항과 목록 열기 버튼 | 편집기 1열을 기본으로 두고, 필요할 때 사실·진단·이력을 우측 패널로 연다. 비교는 폭이 확보될 때 2열 | 카운터 펼치기와 `수정 제안 비교`를 문항 헤더에서 접근 |
| 767px 이하 | 상단에 프로젝트 선택, 메뉴 버튼, 현재 화면 이름. 문항 선택은 버튼으로 목록을 연다 | 본문, 카운터, 작성 동작, 보조 정보 순으로 한 열 목록. 사실과 진단은 개별 펼침 패널, 전체 비교는 위아래 변경 묶음 | 뷰포트 하단에 필요한 주 행동 1개. 키보드가 열리면 고정을 풀고 본문과 포커스를 가리지 않는다 |

최소 지원 폭은 CSS 320px이다. 전체 페이지 가로 스크롤을 방지하고 긴 URL과 기술명을 줄바꿈한다. 편집기 안의 모달·패널에서 동시에 열린 스크롤 영역은 한 곳으로 제한한다. 좁은 화면의 위원회 기준표와 공고 요건 목록은 행의 레이블과 값을 세로로 배열한다.

### 화면의 기본 형태

```text
CareerProof          지원 프로젝트 선택            저장 방식 / 설정
작업 메뉴            문항 제목 / 실행 상태        사실 · 문체 · 이력
문항 목록            작성 본문                   확인 요소와 원문 위치
                     문자 / 바이트 / 줄           보강 질문 또는 변경 기록
                     편집 저장 / 재개 / 확정
```

선택 문항과 해당 본문에 가장 넓은 영역을 준다. 현재 선택과 문장의 근거 연결은 각각 메뉴의 코발트 표시와 본문 밑줄로 표현한다. 동일한 모양의 카드가 반복되지 않도록 문항·기준·사실은 목록과 구분선으로 구성하고, 본문 편집과 레이어에만 표면을 부여한다. 아이콘은 클립보드·펼치기·외부 링크처럼 의미가 익숙한 조작에 사용하고 이름을 제공한다.

| 토큰 | 초기값 | 적용 |
|---|---|---|

| 본문 / 보조 글자 | `#202733` / `#515C6D` | 제목과 본문, 보조 메타데이터 |
| 강조 / 연한 강조 | `#244AC5` / `#EEF2FF` | 주요 버튼, 선택 배경, 포커스 링 |
| 구분선 / 입력 경계 | `#DDDCD5` / `#7A8291` | 비상호작용 구분선, 폼 경계 |
| 주의 | `#744900` / `#FFF2D5` | 제한 임박, 보강 요청, 미검증 프리셋 |

- 글꼴은 `system-ui, "Malgun Gothic", "Apple SD Gothic Neo", "Noto Sans KR", sans-serif`를 기본 제안으로 둔다. 외부 웹폰트 로딩 없이 한국어 글꼴을 사용한다. 페이지 제목 `28/36px`(모바일 `24/32px`), 섹션 제목 `18/26px`, 본문과 버튼 `15/24px`, 편집 본문 `16/28px`, 부가 정보 `13/20px`를 기준으로 한다. 카운터 숫자는 `tabular-nums`를 적용한다.
- 여백 단위는 `4, 8, 12, 16, 24, 32px`. 편집 표면 반경 `8px`, 조작 요소 `6px`. 떠 있는 패널에 가벼운 그림자를 쓰고, 본문 영역은 테두리로 구분한다. 행동으로 열린 패널의 전환은 `120–180ms`, `prefers-reduced-motion`에서 즉시 반영한다.
- 본문 대비 `4.5:1` 이상, 큰 글자·의미 있는 아이콘·포커스 표시 `3:1` 이상을 구현에서 측정한다. 상태는 색상과 함께 `확인 필요`, `제한 임박`, `초과`, `확정` 텍스트 또는 아이콘으로 전달한다. [WCAG 2.2](https://www.w3.org/TR/WCAG22/)

## 3. 시작, 가져오기, 사실 확인

1. 첫 시작은 `새 지원 프로젝트`, `작업 JSON 복원`, `가상 예시 열기`를 제공한다. 제목·회사·직무·문항을 직접 입력할 수 있다. 처음에는 `메모리에서 작업`을 선택한다. `이 기기에 저장` 선택 시 저장 범위와 경로, 재시작 복구 범위를 화면에서 확인한다.
2. `프로필`에서 `직접 입력` 또는 `JSON Resume 가져오기`를 선택한다. 파일 선택을 기본으로 두고 드롭 영역은 보조로 제공한다. 가져오기 미리보기는 경력·프로젝트·기술·학력·자격의 매핑, 누락과 미지원 필드, 로컬 연락처를 표시한다. 잘못된 JSON 및 스키마 오류는 첫 문제 필드와 이유를 보여 주고 재선택할 수 있게 한다. 가져온 필드의 URL은 텍스트로 표시한다.
3. 사실 후보 목록은 `확인 필요`, `확인`, `철회` 상태를 구분한다. 상세에는 실제 행동, 기간, 결과·단위·측정 기준, 주체, 출처 위치가 있다. 출처는 직접 입력 필드, JSON 항목 위치, PDF 페이지, 사용자가 연결한 자료 중 하나로 표시한다. 사용자는 후보별로 `사실 확인`, `고쳐서 확인`, `보류`를 선택한다. 일괄 확인은 제공하지 않는다.
4. 확인된 사실을 문항에 연결한다. 사용자가 `이 문항에 반드시 포함`을 지정할 때 적용 문항 이름을 함께 보여 준다. 사실을 수정·철회하면 영향을 받는 문항과 확정본을 표시하고 `다시 검토`로 편집기에 연결한다. 시각적 우선순위는 확인 여부, 구체 정보, 원문 근거, 사용 문항 순이다.
5. 클라우드 BYOK 사용 시 첫 작성 직전에 제공자와 모델, 전송되는 문항·확인 사실·브리프 범위, 마스킹 미리보기, 예산을 함께 확인한다. API 키 필드는 숨김 입력으로 제공하고 표시/숨기기 버튼을 둔다. Ollama는 로컬 주소·모델 연결과 시간 예산을 확인한다. 설정 없이 직접 편집, 길이 계산, 규칙 진단, 확정·복사를 사용할 수 있다.

## 4. 작성 워크벤치

### 문항·편집·분량

편집기에는 문항 제목, 문서 유형, 원문·구조 가이드 열기, 현재 리비전, 실행 상태를 표시한다. 자소서는 문항별 텍스트 영역, 이력서 양식은 학력·경력·프로젝트 등 구조화 필드, 경력기술서는 항목별 역할·행동·성과·기술을 제공한다. 포트폴리오는 `공고·자료`의 추출 보기와 근거 연결로 이동한다.

- 카운터는 설정된 문자·바이트·줄을 `742 / 1,000자`, `1,310 / 1,500바이트`, `9 / 11줄`처럼 표시한다. 가장 높은 사용률을 상태 기준으로 하되, 사용자가 위반한 제한을 따로 읽을 수 있게 한다. 90% 이상은 `제한 임박`, 정확히 100%는 `한도에 맞음`, 100% 초과는 초과량과 함께 `초과`로 표시한다. CP949 표현 불가 또는 이모지 금지 위반은 문자 위치와 원래 문자를 제시한다.
- `글자 수 규칙`에서 단위·공백·줄바꿈·이모지·인코딩·최대 문자·최대 바이트·최대 줄을 확인한다. `사이트 표시값 맞추기`는 복사 가능한 가상 시험 문자열과 결과 입력을 여러 건 제공한다. 후보가 복수로 남으면 구분용 문자열과 남은 설정 차이를 보여 준다. 확정한 규칙에는 적용 범위와 확인일을 기록하고, 미확인 프리셋에는 `미검증 프리셋`을 붙인다.
- 문체 패널은 `형식·반복`, `상투 표현`, `구체성 부족`을 같은 순서로 보여 준다. 점수 근거를 선택하면 정확한 원문을 보여 주고, 원문을 바꾸지 않은 채 해당 구간으로 이동한다. `참고용`, `보정 전`, 신뢰도를 조건에 따라 표시한다. 점수가 있는 화면에는 `점수는 진단이며 합격 예측이 아닙니다`를 표시한다. 짧은 글에도 관찰한 표현과 원장 근거 보강을 안내한다.
- `외부 검사 결과 기록`은 사용자가 직접 도구 이름, 측정일, 점수, 문서나 문단 범위를 입력하는 폼이다. 해당 범위와 앱의 문체 근거를 나란히 보며 각 도구의 이름과 단위를 그대로 읽는다. 외부 결과는 작성 실행 입력에서 제외한다. `참고 문서와 겹침 확인`을 선택한 경우 직접 제공한 문서에서 겹치는 구간과 비교한 문서 이름을 표시한다.
- 웹 문서의 인용·하이라이트는 코드 포인트 범위를 UTF-16으로 변환하고 정규화·마스킹 전 원문으로 역매핑한다. `C#`, 이모지, 결합형 한글, 같은 문장의 반복을 포함한 원문으로 위치를 확인한다. 스크린 리더와 복사 기능에서 원문을 한 번만 읽고 복사하도록 한다.

### 사실, 수정 제안, 이력

| 컴포넌트 | 표시와 행동 |
|---|---|
| `확인된 사실` 패널 | 현재 문항에서 쓴 근거와 빠진 필수 사실을 보여 준다. 문장과 연결된 사실을 열면 원문 위치·수치·주체·확인 상태를 확인할 수 있다. `사실 추가`가 입력으로 연결된다. |
| `수정 제안 비교` | 기준본과 후보본의 변경 문장을 맞춰 표시한다. 덧붙임/삭제에는 색과 `추가`/`삭제` 레이블을 붙인다. 변경별 주장 근거·게이트 결과와 예상 분량을 묶고, `변경 수락`, `변경 거절`, `직접 수정`을 제공한다. 의존 주장·문장 때문에 함께 반영해야 하면 묶음과 사유를 알린다. |
| `리비전 이력` | 생성 주체, 시각, 분량, 검토 상태와 함께 `현재 편집본`, `추천본`, `확정본`을 각 리비전의 실제 지정 상태에 따라 표시한다. 이전 내용을 편집기로 가져오면 새 리비전으로 연결하고 원래 이력을 유지한다. |
| `근거 보강` | 최대 3개의 질문에 답하고 만들 사실을 검토한다. 질문별 건너뛰기와 `사실 확인 후 재개`를 제공한다. 보강한 수치·기간·역할이 사실 후보에 어떻게 반영되는지 미리 보여 준다. |

수정 제안이 기각되면 사유와 영향 문장을 보여 준다. 근거가 확인되지 않거나 철회된 사실은 `사실 확인 필요`, 필수 사실이 빠지면 `필수 사실 누락`, 분량 위반은 `제한 초과`로 표시한다. 현재 편집본에서 조금씩 수락한 변경도 새 본문으로 재검증한다. 사용자는 기준 원문, 현재 편집본, 추천본 중 유효한 내용을 고르고 `이 답변 확정`을 실행한다. 확정 전 최신 원장·분량 규칙의 검증 결과를 사용한다.

### 실행과 제어

| 상태 | 화면 표시 | 주요 행동 |
|---|---|---|
| 시작 전 | `직접 작성 중` 또는 `작성 준비` | `작성 실행`에서 제공자·예상 비용·반복 횟수와 선택 목표를 확인 |
| `RUNNING` | `초안 작성 중`, `문체 확인 중`, `제안 검토 중`과 반복 `2 / 4` | `일시정지`, `작성 중단`. 본문은 읽기 전용이고 선택·복사는 가능 |
| `PAUSING` | `현재 단계가 끝나면 일시정지합니다` | 진행 표시, 필요 시 `작성 중단` |
| `PAUSED(user)` | `일시정지` | `편집 저장`, `작성 재개`, `실행 취소` |
| `PAUSED(needs_user_input)` | `사실 확인 필요` | 보강 질문, `사실 확인 후 재개`, 직접 편집 |
| `COMPLETED` | `작성 완료` 및 종료 이유(목표 도달, 반복 한도, 개선 정체, 사용자 중단) | 추천본 보기, 직접 편집, `이 답변 확정`, `새 작성 실행` |
| `FAILED` / `CANCELLED` | 실패 사유 또는 `실행 취소됨` | 마지막 유효 리비전, 필요한 경우 연결 설정/새 실행 |

`작성 중단`은 완료 상태로 바꾸고 마지막 추천본을 표시한다. `실행 취소`는 취소 상태와 사용량을 남긴다. 두 동작에서 진행 중이던 결과의 처리와 사용자 편집 유지 여부를 확인 문구에 담는다. 새 이벤트가 오면 상태와 반복 번호만 조용히 알리고 편집 포커스는 유지한다. 진행률을 계산할 수 없는 단일 호출에는 단계 이름을 표시한다.

실행 설정의 `문체 진단 목표`는 선택 입력이다. 목표를 지정하면 유효한 리비전에서만 도달 여부를 평가하는 조건과 짧은 글 보류를 함께 보여 준다. 목표를 비우면 반복·예산·근거 확인 상태가 실행을 제어한다. 자동 실행 종료 후 본문은 사용자가 확인한다. 문항 또는 화면을 전환해도 현재 탭의 미저장 편집을 유지하고, 프로젝트 닫기처럼 편집을 잃을 수 있는 행동에서 `편집 저장`, `저장하지 않고 닫기`, `계속 편집`을 제공한다.

## 5. 공고·포트폴리오 및 위원회

### 공고·자료

1. `공고 원문`에 붙여넣고 회사와 직무, 마감일을 확인한다. Phase 2의 `문항과 제한 추출`은 후보 제목·유형·분량과 원문 부분을 보여 준다. 사용자는 `문항에 추가` 전에 수정할 수 있다. 이미지 공고에서 텍스트가 비면 `텍스트 붙여넣기` 경로를 제공한다. 공고에 표시된 AI 활용 안내의 원문 위치도 보여 준다.
2. `회사 브리프`는 명시 요건과 기타 내용을 원문과 연결한다. 화면에서 `공고에 명시`, `자료에서 추정`, `출처 확인 필요`를 구별한다. 외부 조회 전에 서비스·URL·전송 범위를 명시하고 선택적으로 실행한다. 완료 뒤 적용 자료의 출처, 가져온 시각, 만료 여부와 `다시 조회`를 제시한다.
3. `포트폴리오 자료`는 PDF·Markdown 추가와 공개 GitHub 저장소 URL 확인을 지원한다. 파일에는 원문 페이지/섹션과 파서의 추출 순서를 펼쳐 비교한다. 추출되지 않은 표·열·이미지 텍스트와 빈 추출본에는 `추출 확인 필요`를 표시한다. GitHub 결과는 점검 근거 링크, 확인 시각, 상태를 보여 준다. 접근 제한이나 오류에는 파악 가능한 부분만 표시한다. 실제 역할은 `프로필·사실`에서 사용자가 확인한다.
4. `요건과 근거`의 각 행에 공고 요건, 해당 문장·문서, 상태와 다음 행동을 둔다. 레이블은 `근거 확인`, `언급만 있음`, `근거 없음`과 가져오기 실패의 `자료 확인 필요`로 표기한다. `준비할 일`은 부족한 근거와 할 일, 남길 결과물, 예상 노력 순으로 보여 준다.

### 위원회

1. `위원회 심사`에서 `이 문항` 또는 `전체 지원서`, 입력으로 사용할 리비전, `Fast` 또는 `Deep`, 심사 모델을 선택한다. `블라인드 심사`가 적용된 전송 필드, 예상 호출 수·비용, 작성 모델과 같은 계열을 선택한 경우의 안내를 검토한 뒤 `심사 시작`을 누른다. 편집 중인 미저장 본문이 있는 경우 먼저 저장할지 결정한다.
2. 보고서 상단에 원래 심사 범위, 작성 리비전, 유효 회차수, 실행 방식, 총점 또는 부분 소계와 면책 문구를 둔다. 전체 유효 회차가 있으면 `72 / 100`과 Deep 범위 `68–76`, 회차 3을 표시한다. Fast 한 회에는 유효 회차 1을 표시한다. 전체 유효 회차가 없으면 `부분 소계 57 / 80점`과 누락된 페르소나·사유를 표시한다. 문항 심사는 적용 배점과 비율에 `문항 기준 참고`를 붙인다. 적용 기준이 없으면 `평가 보류`와 범위를 보여 준다.
3. 실무 팀장(20), 실무 팀원(20), 인사 팀장(18), 인사 담당자(17), 임원(25)을 그룹과 함께 보여 준다. 상세에 기준별 등급·배점, 감점 사유, 인용 원문, 수정 제안과 관련 사실을 표시한다. `인용 원문 보기`는 심사한 스냅샷의 문장에 접근한다. 수정 후에는 기존 보고서에 `이전 리비전 평가`를 표기하고 `다시 심사`를 제공한다.
4. 점수 범위 폭이 10점 이상(제안값)이면 `평가 변동 큼`을 범위 옆에서 설명한다. 보고서 아래에 `요건별 보완`과 `준비할 일`을 두고 해당 공고 근거를 펼칠 수 있게 한다. 페르소나별 면접 꼬리 질문은 Phase 2.5 선택 기능으로 연결한다.

## 6. 확정, 내보내기, 이후 기능

내보내기 화면의 첫 항목은 확정된 답변 목록이다. 문항별로 확정 시각, 분량 규칙과 제한, 재검토 상태를 표시한다. `확정 답변 복사`와 `TXT 다운로드`는 선택한 문항의 본문을 미리 보여 준다. 복사가 성공한 뒤 `확정 답변을 복사했습니다`를 안내한다. 클립보드 권한 오류에는 선택 가능한 원문과 `TXT 다운로드`를 제공한다.

`작업 JSON 다운로드`는 초안·리비전·사실과 복구에 필요한 문항을 포함하는 로컬 작업 파일이다. 저장 전 포함 범위와 개인정보 여부를 표시한다. 복원 화면은 파일 버전, 문항·리비전·원장 내부 참조, 불일치 내역을 검증하고 사용자 확인 후 복원한다. JSON Resume는 프로필 가져오기 화면에서 선택한다. `선택한 답변`과 `전체 작업`을 버튼과 파일명에서 구별한다. 현재 원장 기준으로 재검토가 필요한 확정본은 `편집기에서 다시 검토`로 연결하고 공유용 출력에서 제외한다.

| 이후 기능 | 사용자 흐름과 상태 |
|---|---|
| Answer Bank·Tracker, Phase 2.5 | 마스터 답변을 선택해 새 회사의 문항에 파생본을 만들고 원장 연결과 상위 리비전을 유지한다. Tracker는 회사, 마감일, 작성 상태를 목록과 상태 열로 본다. 카드 이동과 같은 역할의 상태 선택 메뉴를 제공한다. |
| PDF 출력, Phase 3 선택 | 확정된 구조화 이력서에서 템플릿과 한글 미리보기를 확인한 뒤 저장한다. 줄 잘림·읽기 순서·폰트가 검증된 템플릿만 목록에 제공한다. |
| Chrome 확장, Phase 4 | `확장으로 보내기` → 대상 탭·권한·문항 매핑 확인 → 선택한 확정 답변 채우기 → 사이트 카운터 대조. 폼 값이 이미 있으면 덮어쓸 필드를 확인한다. 대상·권한 오류에는 `확장용 JSON 다운로드`를 제공한다. 완료 상태는 `입력됨`이며 제출은 대상 사이트에서 사용자가 한다. |

## 7. 예외와 복구

| 조건 | 사용자에게 보이는 상태 | 복구 행동 |
|---|---|---|
| 프로젝트·문항·사실 없음 | 현재 필요한 항목 한 가지를 먼저 제시 | `프로젝트 만들기`, `문항 추가`, `첫 사실 추가` 중 해당 화면의 시작 버튼 |
| 연결 끊김·SSE 재생 대기 | `연결이 끊겼습니다. 실행 상태를 다시 확인하는 중입니다` | 마지막 확인 상태와 시각을 보여 준다. 재연결이나 `다시 연결` 후 마지막 이벤트 다음부터 복구하고 현재 상태를 갱신한다. 미저장 입력을 화면에 유지한다. |
| 제공자 키 없음·만료·인증 오류 | `API 키가 필요합니다`, `키를 확인해 주세요` | 제공자와 모델을 표시하고 `키 다시 입력`을 요청한다. 재개 가능한 체크포인트로 복귀한다. |
| 비용 상한·사용량 미확인 | `비용 한도에 도달했습니다` 또는 `사용량을 확인할 수 없습니다` | 사용/예약 비용과 적용 상한을 표시한다. 상한 부족은 `비용 한도 변경`이나 직접 편집, 미확인은 당시 실행 상세와 제공자 내역을 확인하는 경로를 제공한다. |
| 429·5xx·타임아웃 | `제공자 응답을 다시 기다리는 중` 또는 `제공자 연결 오류` | 제한 내 재시도 중임을 표시하고 소진 시 `작성 재개`와 직접 편집을 제공한다. |
| 409, 다른 탭에서 편집 | `다른 탭에서 답변이 수정되었습니다` | 내 미저장 본문과 최신본을 임시 비교하고 `최신본 불러오기`, `비교 후 저장`, `내 편집 복사` 제공. 재요청은 최신 기준이나 새 명령 상태를 사용한다. |
| 서버 재시작, 메모리 작업 | `작업 본문을 다시 연결해야 합니다` | `작업 JSON 복원` 또는 `새 프로젝트 만들기`. 본문이 준비되면 새 실행을 시작한다. |
| 서버 재시작, 저장된 작업 | `마지막 저장 지점에서 재개할 수 있습니다` | 체크포인트와 문항을 안내한다. 클라우드는 키 재입력 후, Ollama는 모델 확인 후 재개한다. |
| 복원 오류·프로필 가져오기 오류 | `파일을 읽을 수 없습니다`와 파일 종류·버전·필드 오류 | 가져오기 전 편집 상태를 유지하고 가능한 수정사항과 `다른 파일 선택`을 보여 준다. |
| 현재 탭이 오프라인 | `오프라인` 및 현재 사용할 수 있는 행동 표시 | 화면에 남은 편집·카운터·복사를 사용할 수 있게 한다. 저장 전송 실패 시 메모리 보관 표시와 재연결 후 다시 저장을 제공한다. |
| 전체 삭제 | 삭제 전 항목과 로컬 작업의 범위를 확인 | `전체 삭제`를 별도 확인한 뒤 빈 프로젝트 화면으로 이동하고 결과를 안내한다. |

같은 조작을 연속 실행하는 동안 제출 버튼을 잠그고 실행 상태를 알린다. 잔여 이벤트는 Run 식별자와 적용 순서가 현재 상태에 맞을 때 반영한다. 오류 문구와 다운로드 이름에 키·실행 토큰을 포함하지 않는다.

## 8. 접근성과 검증 기준

- `header`, `nav`, `main`과 제목 단계로 구조를 정의하고 `본문으로 건너뛰기`를 제공한다. 작업 메뉴는 링크, 문항 목록은 실제 선택 동작에 맞는 버튼 또는 탭을 사용한다. 탭 사용 시 화살표로 이동하고 `Tab`으로 내용에 진입한다. 폼은 입력과 연결된 레이블, 예시, 필드별 오류를 제공한다. [WAI-ARIA 탭 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)
- 터치 목표는 원칙적으로 `44×44px`. 키보드 포커스 링은 `2px`를 기준으로 두고 배경과 대비를 확인한다. 대화상자에서는 이름과 첫 포커스, 내부 순환, `Esc` 닫기, 연 버튼으로 복귀를 검증한다. 길이 상태·저장 결과·실행 전이는 `aria-live="polite"`로 전달하고 글자 입력마다 읽지 않는다. [WAI-ARIA 모달 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)
- 기본 편집기는 한국어 IME 조합을 보존한다. 조합 중에는 자동 저장 커맨드·확정 단축키를 보내지 않으며, 완료 후 카운터와 본문을 동기화한다. 마우스·터치·키보드에서 수정 제안 수락/거절과 근거 열기가 같은 의미를 갖는다.

| ID | 인수 조건 |
|---|---|
| UX-01 | 가상 예시 진입 시 `workbench`의 `일시 정지` 상태와 `지원 동기` 본문이 보인다. 5개 화면 선택과 돌아가기가 동작하고 현재 화면·문항 선택이 유지된다. 시연에서 `글자 수 보정` 예시로 후보를 좁히고, 제안을 반영·확정한 뒤 TXT와 시연용 작업 JSON을 받는다. |
| UX-02 | 320, 390, 768, 1,024, 1,280, 1,440px에서 가로 넘침 없이 본문과 주요 동작을 읽는다. 200% 확대·모바일 키보드에서도 오류, 포커스, 확정 버튼에 접근한다. |
| UX-03 | 문항별 문자·바이트·줄을 독립 표시한다. 90%, 정확히 100%, 초과, CP949 불가 및 결합형 한글에서 상태와 값이 구현 규칙과 일치한다. 규칙 후보가 모호하면 새 시험 문자열로 구분한다. |
| UX-04 | 일시정지 요청 후 단계 완료 전에 본문 편집을 열지 않는다. 편집 저장 후 재개 시 새 리비전에 연결한다. 409에서는 내 미저장 입력과 최신본을 모두 확인할 수 있다. |
| UX-05 | 수치·귀속이 바뀐 AI 제안의 근거 실패와 필수 사실 누락을 원문에서 확인한다. 승인되거나 섞어 수락한 본문을 재검증하고, 사실 철회 시 관련 확정본을 다시 검토하게 한다. |
| UX-06 | 짧은 글은 참고 상태와 함께 표시한다. 세 가지 문체 축과 인용 근거가 접근 가능하고, 인용 범위는 한글·이모지·중복 문장 데이터에서 정확히 일치한다. |

| UX-08 | 공유 출력은 검증된 확정 답변만 포함한다. 작업 JSON은 별도 미리보기로 범위를 확인하고 스키마·원장 참조가 유효한 샘플을 복원한다. |
| UX-09 | 오프라인, 재연결, 키 만료, 사용량 미확인, 서버 재시작에서 문구와 후속 버튼이 상태에 맞는다. 포커스는 사용자가 시작한 화면 또는 오류 위치로 복귀한다. |
| UX-10 | 키보드만으로 시작 → 문항 선택 → 사실 열기 → 수정 제안 검토 → 확정 → 복사가 가능하다. 상태를 색 없이 구분하며 스크린 리더가 오류·버튼 이름·버튼 상태를 읽는다. |

검증 기록에는 확인 환경과 실제 동작 범위를 표기한다. 스크린샷과 반응형 확인은 `PRESENTABLE`의 근거이며, 브라우저 조작과 데이터·실행 연동 결과는 해당 기능별 `VERIFIED`의 근거다.

## 9. 실제 제품 화면과 비교한 결과

2026-11-27에 v0.3 프로토타입을 만든 뒤 공개 화면을 비교했다. 초기 설계에서 조사한 기능과 이번에 직접 관찰한 화면을 구분하기 위해 확인 방법을 함께 적었다.

| 제품 · 확인 방법 | 실제 화면에서 관찰한 점 | CareerProof에 적용할 기준 |
|---|---|---|
| **OpenResume** · 공개 파서에서 기본 예제 PDF 선택 | 왼쪽 원본 PDF를 보면서 오른쪽에서 프로필·학력·경력 필드가 채워지는 결과를 확인할 수 있다. [공개 파서](https://www.open-resume.com/resume-parser) | 가져오기 화면에서 후보를 선택하면 해당 원본 페이지·구간과 추출값을 함께 표시한다. 사용자 확인을 마친 항목을 작성 근거로 연결한다. |
| **Reactive Resume** · 공식 편집기 캡처와 제안 카드 상세 확인 | 수정 위치와 대상 문단을 연결한다. 카드에는 수정 전후, 인용한 경력 원문, 확인이 필요한 수치, 수락·편집·거절 동작이 함께 보인다. [공식 가이드와 캡처](https://docs.rxresu.me/guides/using-the-assistant) | 현재 시연의 사실 ID는 오른쪽 원장 항목으로 포커스를 옮긴다. 제품에서는 제안 카드 안에서도 근거 원문과 측정 조건을 펼쳐 수락 여부를 결정하게 한다. |
| **자소설닷컴** · 공식 도움말의 자기소개서 편집기 캡처 확인 | 상단 저장 버튼 옆에 마지막 저장 상태가 표시되고, 친구 첨삭은 오른쪽 패널에서 확인한다. [공식 도움말](https://jasoseolsupport.zendesk.com/hc/ko/articles/12816695839503) | 편집 중에도 본문을 보면서 피드백을 읽게 한다. 저장 상태는 실제 보관 모드에 맞춰 `이 탭에서 편집 중`과 `이 기기에 저장됨`으로 표시하고, 제출용 리비전에는 별도로 `확정본`을 표시한다. |
| **Teal Job Matcher** · 공식 제품 소개 이미지와 도움말 확인 | 공고의 직무·회사와 요구 키워드 목록을 함께 보여 주고, 이력서 반영 여부를 키워드별로 표시한다. [제품 소개 이미지가 있는 페이지](https://www.tealhq.com/tool/resume-job-description-match) · [공식 사용 가이드](https://help.tealhq.com/en/articles/12060992-using-the-job-matcher) | 공고 브리프에서는 각 요건에 `근거 있음`·`언급만 있음`·`확인할 근거 없음`을 문자로 표시한다. 근거가 있는 요건을 선택하면 해당 문항과 사실을 확인할 수 있어야 한다. |

우선 반영할 제품 동작은 수정 제안 안에서 근거를 펼치는 것이다. 모바일 한 열 화면에서 사용자가 긴 문서를 오간 뒤 원래 제안을 다시 찾는 수고를 줄일 수 있다. 인수 조건은 근거를 펼치고 닫아도 편집 본문·선택 문항·스크롤 위치가 유지되고, 키보드로 같은 제안의 수락 또는 거절까지 이어갈 수 있는 것이다. 이 동작은 제품 설계에 추가한 항목이다.
